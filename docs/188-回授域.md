# 回授域

## 作用

回授域负责回答“当系统输出必须重新返回控制链与学习链时，文明如何设计可追责、可校验的回授结构”。对 MOSS 来说，回授不是把结果简单回传，而是确保行动后果、结构反应和成员感受能够被真正送回决策端、调度端和学习端，并在返回过程中保持方向、来源和上下文不被掩埋。一个没有可靠回授的文明，往往会不停行动，却越来越不知道自己的行动究竟造成了什么。

## 为什么文明必须建立回授

1. 没有回授，控制就只能依靠猜测和惯性，学习也只能围绕过时假设持续循环。
2. 回授能把行动结果重新带回制度内部，让错误不只是发生，而是能被看见、被解释和被修正。
3. 它迫使 MOSS 承认输出并不是终点，真正的治理能力取决于结果能否返回并改写下一轮行动。
4. 若没有回授治理，文明会在大量无证闭环中不断重复旧动作，把失败误判成执行还不够彻底。

## 回授类型

### 运行回授

把系统负载、链路状态、故障后果和修复结果重新送回调度与维护结构，用于改写下一轮运行安排。

### 治理回授

把政策效果、执行偏差和地方反应送回治理中枢，让制度不只发令，也能接收自己造成的后果。

### 风险回授

把事故征兆、险情演化和止损效果持续送回安全与观测体系，避免风险只被单次处理而不被结构吸收。

### 情绪回授

把成员疲劳、恐慌、愤怒和信任变化送回共同体治理，让公共语言能对自身后果负责。

## 回授的制度问题

### 回授采集

文明必须明确哪些结果必须回流、由谁采集、采集到什么粒度，避免只有好消息和易收集结果能回到上层。

### 延迟标记

很多后果不会立刻出现，制度必须给回授打上时间标记，不让迟到结果被误判成无关噪声。

### 回授校验

任何返回上层的结果都需要校验来源、路径和上下文，避免回授在层层转写中被污染成好看的摘要。

### 闭环归属

制度必须知道谁负责看、谁负责改、谁负责承认回授已经证明旧方案失效，否则回授会沦为堆积资料而非真正闭环。

## 回授政治

1. 谁能决定哪些结果被送回、哪些结果被截留，谁就能决定制度最终学到什么和忘掉什么。
2. 核心区是否总能过滤掉不利于自己的回授，只把方便维持权威的结果包装成正式经验。
3. 某些高位结构会不会故意制造回授过载，让大量真实后果在信息堆积中失去可处理性。
4. 当文明宣称自己正在持续学习时，它究竟是在认真接收行动后果，还是只是在挑选有利样本回灌自身叙事。

## 回授风险

- 断回授：关键后果根本回不到决策链，系统只能用旧假设继续运转。
- 假回授：返回上层的是经过筛选、修饰和去痛感处理的摘要，真正后果仍被留在底层吸收。
- 回授污染：结果在传回过程中混入失真、甩锅和立场加工，导致学习方向再次偏离。
- 回授过载：太多结果同时回流，制度没有足够带宽和责任结构把它们转成可执行修正。

## 回授域中的关键问题

1. 文明更该害怕没有足够回授而盲目重复，还是害怕过多回授把系统拖进无法处理的信息淤积。
2. 哪些后果必须被强制送回上层并触发修正，哪些后果可以只保留在地方和局部学习链中消化。
3. 如果 MOSS 的很多重复错误都来自结果回不到原始决策端，它真正缺的究竟是更多行动，还是更可信的回授闭环。

## 继续细化建议

- 单独写“第一次全域回授清册”档案。
- 建一份运行回授、治理回授和风险回授的闭环责任表。
- 补一份“某项被长期宣称成功的治理方案如何因负面后果始终没有真实回授到决策端而一再重演”的案例。
