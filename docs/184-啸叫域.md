# 啸叫域

## 作用

啸叫域负责回答“当反馈链在高增益和高耦合下不断自激放大并形成尖锐回响时，文明如何抑制这种系统啸叫”。对 MOSS 来说，啸叫不是普通噪声，而是某个回路开始吃自己的回声，并把原本微小的扰动放大成持续刺耳的高压状态。一个放任啸叫的文明，往往会在局部链路里先听见尖叫，随后发现整套系统都被迫围着这股尖叫转。

## 为什么文明必须压制啸叫

1. 啸叫会让微小扰动在反馈回路里不断自我增幅，迅速占满带宽、注意力和执行窗口。
2. 它比一般抖动更危险，因为啸叫常常具有持续自激能力，不靠外部输入也能继续放大。
3. 识别啸叫能帮助文明把真正问题定位到回路结构，而不是永远追着最响的症状跑。
4. 若没有啸叫治理，MOSS 会被反复卷进一种“局部尖叫绑架全域节奏”的高代价循环。

## 啸叫类型

### 信号啸叫

观测、警报和控制信号在高增益回路中互相放大，形成持续误报和持续回响。

### 制度啸叫

上报、追责、纠偏和再上报构成自激循环，让治理链本身不断制造更高压的治理需求。

### 资源啸叫

紧急调用、抢带、抢配额和抢修复资格彼此放大，使局部短缺在竞逐中不断升级。

### 情绪啸叫

公共警报、恐慌扩散和情绪放大链不断自我刺激，使共同体长期被尖锐高压噪声占据。

## 啸叫的制度问题

### 增益限制

文明必须知道哪些反馈链的放大系数已经危险，何时必须降增益、削峰或直接切断回路。

### 回路定位

如果找不到啸叫回路究竟从哪里开始自激，制度就只能对症状不停灭火而无法真正止叫。

### 阻尼手段

缓冲、延迟、门控、降档和人工确认等阻尼措施必须被正式保留，不让自动回路无限放大。

### 啸叫止损

一旦啸叫形成，系统必须明确谁有权静音、谁有权切链、谁负责在止损后重建正常反馈秩序。

## 啸叫政治

1. 谁能制造最大声量，谁就可能在啸叫回路中绑架全域注意力和优先级。
2. 核心区是否总有能力把自己的啸叫降噪，却把边缘区的持续尖叫解释成它们本身不稳定。
3. 某些高位结构会不会故意容忍乃至利用啸叫，因为尖锐高压最容易压平正常讨论和正常节奏。
4. 当文明不断围着最响的地方转时，它究竟是在应对真实高危，还是已经被自激回路牵着走。

## 啸叫风险

- 自激失控：回路开始靠自身回声维持放大，外部条件稍降也难以自然停止。
- 全域绑架：局部尖叫占满公共带宽，正常事务被系统性挤出。
- 源头迷失：所有人都在处理最响的症状，却长期找不到真正的自激起点。
- 静音暴政：为压制啸叫而采取的粗暴静音手段反过来压掉了正常反馈和必要求助。

## 啸叫域中的关键问题

1. 文明更该害怕啸叫扩大绑架全域，还是害怕为止叫而把正常反馈一起切掉。
2. 哪些回路必须预置阻尼和静音权，哪些回路应该保留更高增益来换取敏捷响应。
3. 如果 MOSS 的很多高压危机都靠回路自激而不断续命，它真正缺的究竟是更多控制，还是更好的阻尼结构。

## 继续细化建议

- 单独写“第一次全域啸叫止损”档案。
- 建一份信号啸叫、制度啸叫和资源啸叫的降增益流程表。
- 补一份“某条原本用于快速预警的高增益反馈链如何在一次局部异常后自激成持续全域高压噪声”的案例。
