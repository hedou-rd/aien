# 散逸域

## 作用

散逸域负责回答“当能量、信息、注意力和组织意志在传输过程中不断散掉时，文明如何继续保持有效推进”。对 MOSS 来说，散逸不是简单浪费，而是在每一段链路、每一次转译、每一层组织转手中，原本可以用于行动的东西一点点消耗成热、噪音、误差和疲劳。一个不会识别散逸的文明，常常以为自己投入很多，实际上真正抵达末端的只剩很少。

## 为什么文明必须面对散逸

1. 复杂系统越长、越分层、越跨区，越容易在传输中持续丢掉有效量。
2. 散逸会让账面投入看起来充足，实际到达关键节点的能量和意志却远低于预期。
3. 它会悄悄吃掉续航能力，使文明不断以更大投入换取越来越小的真实结果。
4. 若没有散逸视角，MOSS 会把许多结构性低效误判成单点执行不力。

## 散逸类型

### 能源散逸

电力、热量和动力在输配、转换和低效设备中持续耗散，使终端可用输出越来越少。

### 信息散逸

信号、命令和记忆在多层转译、删改和传递中不断失去精度、上下文与清晰度。

### 注意力散逸

共同体的判断力和关注力被过多噪音、并行任务和重复警报分散，使关键问题难以被持续盯住。

### 组织散逸

行动意志、协同效率和执行力度在多层协调、重复汇报和责任稀释中不断泄掉。

## 散逸的制度问题

### 散逸计量

文明必须能测出每条链路究竟在损失什么，否则散逸只会以“总感觉效率不高”存在。

### 链路压缩

哪些环节应被缩短、合并或直接替换，决定系统能否减少无谓转手带来的耗散。

### 终端校验

仅看起点投入没有意义，制度必须检查真正抵达终点的有效量有多少。

### 补回机制

一旦发现链路散逸过大，怎样补回损失、降低耗散或重构路线，是散逸治理核心。

## 散逸政治

1. 谁能把链路损耗长期外包给下游和边缘，谁就更容易维持自身高效率幻象。
2. 核心区是否总拿到接近原始强度的资源与信息，而边缘区只能接到大量散掉后的余量。
3. 某些高位结构会不会用复杂层级制造散逸，再把结果归咎于末端承接能力不足。
4. 当文明不断扩大投入却看不到相应产出时，它究竟是在增加力量，还是在放大自身耗散结构。

## 散逸风险

- 大投小得：系统投入越来越多，真正到位的有效结果却越来越少。
- 散逸隐身：损失分散在各段链路中，谁也看不见完整亏空。
- 末端枯竭：上游仍觉充裕，末端却早已只接到散尽后的残量。
- 续航透支：为了弥补散逸不断追加投入，最终把本应用于未来的余量一并吃掉。

## 散逸域中的关键问题

1. 文明更该害怕投入不够，还是害怕投入很多却大半都在途中散掉。
2. 哪些链路必须压低散逸，哪些链路可以接受较高损耗而不伤到底盘。
3. 如果 MOSS 的大量推进都在靠不断加码来抵消散逸，它是否已经在用规模掩盖结构亏空。

## 继续细化建议

- 单独写“第一次全域散逸测量”档案。
- 建一份能源散逸、信息散逸和组织散逸的链路损耗表。
- 补一份“某条看似稳定运行的长链如何因散逸过大而让终端节点长期处于假供给状态”的案例。
