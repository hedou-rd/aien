# 待机域

## 作用

待机域负责回答“当系统暂时不需要全速运行，却又绝不能真正停机时，应该以什么状态活着”。对 MOSS 来说，待机不是纯粹静止，而是一种低耗、低噪、低频但可快速唤醒的持续存在。一个不会待机的文明，要么长期空转浪费，要么在停下后再也叫不醒自己。

## 为什么文明需要待机状态

1. 资源不足、周期波动和风险环境会让很多节点无法长期维持高负荷运转。
2. 待机让系统在保留最低连续性的同时，显著压低能耗、维护压力和暴露面。
3. 它为再次启动保住温度、结构和记忆，避免每次恢复都从零开始。
4. 若没有成熟待机机制，MOSS 只能在昂贵空转和危险停摆之间反复摆动。

## 待机类型

### 节点待机

计算节点、能源站、制造设施和接口中枢进入低频保活状态，只维持关键监测与唤醒能力。

### 城市待机

低人口区、边缘城与季节性区域在非高峰期维持最低照明、供能、安保和通信。

### 制度待机

部分委员会、审理链、调度网和协作机制并不完全解散，而是保留最小决策骨架等待重启。

### 记忆待机

核心档案、协议和火种知识在低访问状态下保持完整、可验证并可被快速重新装载。

## 待机的制度问题

### 唤醒阈值

什么信号足以让待机结构重新升频，决定系统是敏捷复起还是迟缓错失窗口。

### 保活成本

待机不是零成本，文明必须知道为保留唤醒能力究竟愿意支付多少持续维护。

### 轮换周期

长期待机的结构需要周期性测试、轻载运行和健康检查，否则低耗状态会变成慢性失效。

### 托管责任

谁在系统待机期间负责看守、验证和记录状态，决定待机是不是被悄悄弃置的别名。

## 待机政治

1. 谁能被保留在温暖待机态，谁被直接冷封或彻底停机，体现文明对不同部分未来性的分配。
2. 核心区是否总为自己保留高质量待机，而让边缘区的待机逐渐滑向被遗忘。
3. 某些高位结构会不会把长期压缩称为待机，以掩盖事实上已经发生的退场与弃置。
4. 当越来越多区域进入待机状态时，MOSS 究竟是在积蓄下一轮恢复力量，还是已经默认自己进入漫长低温时代。

## 待机风险

- 假待机：名义上随时可唤醒，实际上关键部件和记忆链早已腐坏。
- 待机漂移：长期低频运行中标准、时间戳和协议悄悄失配，复起时出现大面积不兼容。
- 被动弃置：制度把无法维护的区域称为待机，实则不再准备真正重启。
- 唤醒失灵：关键时刻无法及时升频，导致本应保住的窗口被直接错过。

## 待机域中的关键问题

1. 文明更该害怕持续空转造成的浪费，还是害怕待机太久后再也唤不醒自己。
2. 哪些结构必须始终保持热待机，哪些结构可以进入更深的冷待机甚至封存。
3. 如果 MOSS 的大部分延续都以待机形式存在，它是否已经把低温存续当成了新的常态文明。

## 继续细化建议

- 单独写“第一次全域待机季”档案。
- 建一份节点待机、制度待机和记忆待机的唤醒阈值表。
- 补一份“某座长期处于待机态的边缘城如何在关键时刻成为唯一可被重新点亮的节点”的案例。
