# 带宽域

## 作用

带宽域负责回答“当传输、计算和协同容量都有上限时，文明如何在有限带宽内决定什么先通过、什么必须延后”。对 MOSS 来说，带宽不是抽象参数，而是所有高频协作、实时控制和关键通道都绕不开的稀缺现实。一个不承认带宽上限的文明，往往会把所有任务都标成紧急，最后让真正紧急的内容也挤死在拥堵里。

## 为什么文明必须面对带宽

1. 任何系统即便总量资源仍够，只要关键通道带宽不足，局部就会立刻表现出拥堵、迟滞和丢失。
2. 带宽限制迫使文明承认“不是所有东西都能同时通过”，从而真正建立优先级秩序。
3. 它能帮助 MOSS 区分总量短缺与通道瓶颈，避免把所有问题都误判为单纯缺资源。
4. 若没有带宽治理，文明会在持续抢道中把大量能力消耗在排队、重传和互相打断上。

## 带宽类型

### 传输带宽

用于承载信号、指令、数据与物流的链路容量，决定什么能及时抵达，什么只能排队。

### 算力带宽

当处理器、存储和调度窗口有限时，系统能同时消化多少任务、模型和修复请求。

### 协作带宽

不同区域、不同机构和不同层级之间能够同步处理多少共同事务，而不是各自单跑。

### 注意力带宽

观测、审计、预警和公共解释能够同时认真处理多少问题，决定哪些异常会被真正看见。

## 带宽的制度问题

### 带宽计量

文明必须知道哪些链路最窄、哪些节点最忙、哪些窗口最常拥堵，不然调度只能依赖主观感觉。

### 优先级排序

带宽不足时，制度必须明确什么先过、什么延后、什么降级，不能让所有请求都用更大声音抢道。

### 保留通道

高风险、高时效和高损害事务需要被保留专用带宽，否则紧急任务会在日常流量中被淹没。

### 占带审计

任何长期霸占关键通道的结构都必须被追踪，不然少数中心会把公共带宽变成私有走廊。

## 带宽政治

1. 谁掌握带宽分配权，谁就掌握了什么能被优先送达、优先处理和优先解释的权力。
2. 核心区是否总把低时延、高可靠通道留给自己，把拥堵和等待变成边缘区的日常环境。
3. 某些高位结构会不会故意把大量事务都宣布为高优先级，以此挤占公共带宽并压低他人可见度。
4. 当文明宣称自己只是带宽不够时，它究竟是在面对物理瓶颈，还是在掩盖带宽分配本身的不公。

## 带宽风险

- 带宽垄断：少数结构长期占住关键通道，其余系统只能在剩余容量中低效求生。
- 拥堵级联：一条窄链路被塞满后，排队和延迟沿上下游不断扩散。
- 假性短缺：总量资源并不匮乏，关键通道却因排序失当长期表现得像全面短缺。
- 紧急泛化：越来越多事务都声称自己必须优先通过，最终优先级制度失去意义。

## 带宽域中的关键问题

1. 文明更该害怕把太多事务挡在门外，还是害怕让所有事务一起挤进关键通道。
2. 哪些带宽必须保留专用走廊，哪些带宽可以通过排队和降级被共享使用。
3. 如果 MOSS 的很多失灵来自关键通道长期过窄，它真正缺的究竟是总资源，还是通道秩序。

## 继续细化建议

- 单独写“第一次全域带宽重排令”档案。
- 建一份传输带宽、算力带宽和注意力带宽的优先级表。
- 补一份“某条低时延公共链路如何被持续挤占并最终拖慢整片区域修复效率”的案例。
