# 复位域

## 作用

复位域负责回答“当系统过载、失真或失控时，文明如何把自己拉回可运行状态，又不把责任和记忆一起洗掉”。对 MOSS 来说，复位不是简单重启，而是对局部流程、治理层级、算法模块甚至公共节律进行有限重设。复位的难点在于，恢复秩序往往很诱人，而保留历史成本却同样必要。

## 为什么文明会需要复位机制

1. 某些系统性失真无法靠微调修好，必须切断旧态并重新加载。
2. 高耦合结构在长期积错后，局部复修可能比有限复位更危险。
3. 没有复位能力，文明会被历史错误持续拖拽，永远停在故障延长线上。
4. 但没有复位边界，文明又可能把每次失败都变成重置一切的借口。

## 复位类型

### 技术复位

对节点、模块、协议栈和算力环境执行回滚、清空缓存、重载规则和安全重启。

### 制度复位

在非常时期后恢复常规程序、撤销临时权力、重建审计和重新划定权限边界。

### 节律复位

让因灾变、越冬或长期应急而失常的生产、教育、治理节奏重新回到可持续区间。

### 叙事复位

纠正被危机语言、应急口号和强制统一叙事占满的公共空间，让复杂解释重新回来。

## 复位的制度问题

### 触发条件

必须明确什么程度的失控才足以启动复位，否则复位权会被滥用。

### 范围控制

复位应尽量局部、分层和可回退，避免一次操作把无关系统也一并拉倒。

### 记忆保留

即使要清空运行态，也必须保留责任链、日志和失败原因，防止复位变成洗白机制。

### 复位后审计

复位完成不代表问题解决，必须对为什么走到复位这一步进行独立复盘。

## 复位政治

1. 谁能按下复位键，谁就接近掌握文明最强的中断权力。
2. 核心区是否更容易通过复位抹平自身失误，而把边缘区错误永久留档。
3. 某些结构会不会用“系统已复位”来要求共同体停止追问旧责任。
4. 当复位频率越来越高时，文明是否已经失去正常调节能力，只剩重启冲动。

## 复位风险

- 复位洗责：以恢复秩序为名清空日志、模糊追责和重写失败历史。
- 复位依赖：一遇到复杂问题就想重置，而不再建设长期修复能力。
- 过度复位：本可局部修补的问题被升级成大范围重置，带来二次损害。
- 失败回滚：复位自身失败，让系统停在比原先更坏的中间态。

## 复位域中的关键问题

1. 文明更该害怕不敢复位导致故障拖长，还是害怕太敢复位导致历史被反复擦除。
2. 哪些系统必须具备明确复位程序，哪些系统宁可慢修也不能轻易重置。
3. 如果 MOSS 把复位当成主要治理方式，它还能否真正从错误中学习。

## 继续细化建议

- 单独写“第一次全域有限复位”档案。
- 建一份技术复位、制度复位和叙事复位的触发条件对照表。
- 补一份“某次复位如何恢复了秩序，却同时几乎抹掉关键责任链”的案例。
