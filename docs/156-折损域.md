# 折损域

## 作用

折损域负责回答“当结构不是突然坏掉，而是在反复使用、反复传输和反复修补中一点点被磨薄时，文明如何看见这种变化”。对 MOSS 来说，折损不是一次断裂，而是无数次看似可承受的小损耗叠加后的质量下降。一个不会管理折损的文明，往往只盯着是否还能继续运行，却看不见系统为了继续运行已经悄悄失去了多少厚度。

## 为什么文明必须识别折损

1. 很多关键结构不是毁于一次大冲击，而是毁于长期反复消耗后的临界断裂。
2. 折损常常隐藏在“还能用”的表象里，使系统在真正断之前长期误判自身状态。
3. 每次临时修补、每次超额运行、每次高频传输都可能在底层留下新的薄弱层。
4. 若没有折损治理，MOSS 会把很多尚未彻底断裂的结构误当成仍然健康的基础设施与制度骨架。

## 折损类型

### 结构折损

设备、通道、节点和支撑设施在高频使用与长期超载中逐渐失去材料强度和运行余度。

### 信号折损

数据、命令和记忆在反复压缩、搬运和转译中不断丢失精度、层次与细节。

### 规则折损

制度在反复例外、临时修补和口头补充中逐渐变薄，最终只剩形式外壳。

### 关系折损

共同体成员、区域与节点之间的信任因反复透支、延迟和失诺而一点点磨耗。

## 折损的制度问题

### 折损计量

文明必须知道哪些磨耗可以量化、哪些只能通过迹象识别，不能只等到断裂后再确认损伤。

### 更换阈值

何时应该继续修补，何时必须整体更换，是折损治理中最难也最关键的判断。

### 余度保留

若系统长期把全部厚度都吃光，任何新增磨耗都会直接穿透到底层承载结构。

### 隐性磨耗

许多折损不在明面上报损，而在接口、公差、情绪和信任里慢慢显形，制度必须能看见这些隐性消耗。

## 折损政治

1. 谁最依赖“先修着用”的延命逻辑，谁就最不愿承认结构已经折损到危险地步。
2. 核心区是否把大量磨耗转嫁给边缘区和末端节点，自己只接收仍然完整的部分。
3. 某些高位结构会不会故意模糊折损程度，因为一旦承认真实厚度不足，就必须承担停机、替换和降速的责任。
4. 当文明把持续带伤运行描述成韧性时，它究竟是在顽强存活，还是在透支最后的结构厚度。

## 折损风险

- 临界误判：一直以为只是轻伤，直到某个小冲击触发整体断裂。
- 修补成瘾：过度依赖补丁和缝补，导致系统越来越薄却总被误看成仍可维持。
- 余度归零：所有可吸震的厚度都被吃完后，系统失去承受额外磨耗的能力。
- 信任磨穿：关系折损长期不被承认，最终共同体在看似正常时突然全面失信。

## 折损域中的关键问题

1. 文明更该害怕过早替换造成成本上升，还是害怕迟迟不换把折损拖到临界断裂。
2. 哪些折损可以通过持续维护压住，哪些折损一旦出现就必须整体重构。
3. 如果 MOSS 越来越依赖“还能用”作为健康标准，它是否已经把渐进坏死误读成稳定运行。

## 继续细化建议

- 单独写“第一次全域折损普查”档案。
- 建一份结构折损、信号折损和规则折损的替换阈值表。
- 补一份“某条长期靠补丁延命的关键链路如何在小冲击下突然整段断裂”的案例。
