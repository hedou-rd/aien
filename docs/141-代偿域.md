# 代偿域

## 作用

代偿域负责回答“当一个子系统失能、失速或失血后，谁来替它扛下原本不属于自己的负担”。对 MOSS 来说，代偿不是单纯补位，而是某些节点、区域和制度长期替另一些失效部分继续承担能耗、算力、维护、风险和情绪成本。一个不会识别代偿的文明，往往会把某些部分的默默超载误认成它们天生就该更能吃苦。

## 为什么文明必须识别代偿

1. 复杂系统很少会在某一处失能后立刻完全停摆，往往是别处先被迫顶上去。
2. 代偿能短期保住连续性，却也会把隐蔽透支转移到新的承压点上。
3. 很多真正的危机不是第一处故障，而是代偿结构被长期榨干后的第二次断裂。
4. 若不追踪代偿链，MOSS 会持续误判哪些部分真的强、哪些部分只是被迫多扛。

## 代偿类型

### 能源代偿

部分能源站、储能带和输配节点长期替掉线或低效区域承担额外负载。

### 算力代偿

某些核心计算节点持续代跑边缘区任务、补算缺口或承接被削减的公共计算需求。

### 治理代偿

上级结构、临时委员会或邻近共同体长期替失能区域做判断、调度和裁决。

### 情绪代偿

少数成员、媒介结构或边缘群体长期承担本应由共同体分担的安抚、解释和情绪吸震工作。

## 代偿的制度问题

### 代偿识别

文明必须能分清什么是短期互助，什么已经变成长期不对称负担。

### 期限边界

代偿若没有时限和退出条件，就会从应急安排变成被默认的永久榨取机制。

### 补回规则

谁来补偿代偿方消耗掉的资源、寿命和信誉，决定代偿是共同体互保还是单向抽血。

### 终止条件

原失能部分什么时候必须恢复自担，或者正式承认结构重组，是代偿链能否停止的关键。

## 代偿政治

1. 谁总在替别人扛，谁就最容易被文明自然化为“本来就应该更耐受”。
2. 核心区是否把边缘区、低优先级岗位和沉默共同体长期设成默认代偿池。
3. 某些高位结构会不会把失能的代价藏进代偿链里，让真正亏空永远不出现在正式账面。
4. 当文明夸耀自己很有韧性时，它究竟是在称赞体系健壮，还是在美化某些部分长期被榨干的现实。

## 代偿风险

- 代偿固化：原本临时顶上的负担慢慢被当成代偿方的常规职责。
- 隐性榨取：代偿消耗长期不进账，直到承压点突然熄火才第一次被看见。
- 双重透支：既没有修好原失能部分，又把代偿方一并拖入衰竭。
- 补偿失踪：系统在恢复后享受代偿收益，却不返还任何资源、地位和时间。

## 代偿域中的关键问题

1. 文明更该害怕没有代偿导致当场停摆，还是害怕长期代偿把更多结构一起拖垮。
2. 哪些代偿应被视为必要互保，哪些代偿已经越界为制度化榨取。
3. 如果 MOSS 的稳定总靠少数节点长期代偿，它是否已经把不平等写成了运行底座。

## 继续细化建议

- 单独写“第一次代偿链审计”档案。
- 建一份能源代偿、治理代偿和情绪代偿的时限规则表。
- 补一份“某条被忽视多年的代偿链如何在第二次冲击中整段熄火”的案例。
