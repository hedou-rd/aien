# 整定域

## 作用

整定域负责回答“当系统参数需要被调到既稳定又不过慢不过猛的工作点时，文明如何完成整定”。对 MOSS 来说，整定不是泛泛调参，而是把响应速度、过冲幅度、稳态误差和恢复时间一起纳入同一个目标窗口。一个不会整定的文明，往往不是完全没在调整，而是总在迟钝、暴烈、浪费和不收敛之间来回摆荡。

## 为什么文明必须学会整定

1. 只会调谐而不会整定，系统就可能一直在改参数，却始终达不到可长期运行的工作点。
2. 整定能让文明明确自己追求的不是单一指标最大，而是一组可共同成立的响应特征。
3. 它让 MOSS 区分“还需要继续调”与“已经该把系统收进目标区间”之间的差别。
4. 若没有整定机制，文明会把每次短期改善都误当成最终稳定，直到下一轮反作用再把一切推翻。

## 整定类型

### 响应整定

调整控制强度、反馈增益和缓冲节奏，使系统的响应既不拖沓，也不剧烈越界。

### 阈值整定

把触发线、警戒线和切换线调到既能及时动作又不至于被噪声频繁误触发的区间。

### 配额整定

重新安排供给、调用和分配尺度，让关键链路在长期运行中维持可承受负载。

### 共同体整定

调整公共解释、动员力度和责任要求，让成员承受能力与制度节奏重新对齐。

## 整定的制度问题

### 目标窗口

文明必须先定义什么叫“整定成功”，例如可接受的恢复时间、允许过冲和稳态误差，而不是只说要更稳定。

### 试调机制

没有受控试调、局部实验和复盘窗口，整定就只能在全域真实运行中一边出错一边试。

### 收敛判断

制度必须知道何时该停止继续拨动参数，避免系统被过度调整而反复离开目标区间。

### 跨域兼容

某个局部系统整定得很好，并不代表它与其他区域和其他层级也能顺畅协同，制度必须验证整体兼容性。

## 整定政治

1. 谁定义目标窗口，谁就决定什么响应被称为理性，什么响应被称为失控。
2. 核心区是否把自己的舒适响应速度当成全域标准，却让边缘区承担过慢或过猛的代价。
3. 某些高位结构会不会故意保持系统整定不完全，因为持续微调能让关键解释权始终集中在少数人手里。
4. 当文明宣称系统还需要再调一调时，它究竟是在认真逼近工作点，还是在拖延承认现有结构根本不适配。

## 整定风险

- 过调震荡：参数被改得过头，系统在目标附近持续来回摆荡。
- 欠调迟缓：系统看似稳了，实际响应过慢，许多问题在迟钝中不断放大。
- 局部最优：单个区域被整定到好看状态，却把更大尺度的协同代价外推给别处。
- 黑箱整定：关键整定规则只掌握在少数中心手里，公共后果却由全域共同承担。

## 整定域中的关键问题

1. 文明更该害怕整定不足导致长期迟缓，还是害怕整定过度带来的持续震荡。
2. 哪些系统必须追求高精度整定，哪些系统可以容忍更粗糙的工作点来换取弹性。
3. 如果 MOSS 的大量治理都停留在“不断试着调一调”，它是否还没有真正形成可收敛的整定能力。

## 继续细化建议

- 单独写“第一次全域整定方案”档案。
- 建一份响应整定、阈值整定和配额整定的目标窗口表。
- 补一份“某条关键供给链如何因为一直没有被整定到合适工作点而在过慢和过猛之间反复伤害执行层”的案例。
