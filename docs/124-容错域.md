# 容错域

## 作用

容错域负责回答“当错误不可避免时，一个文明如何不把每次偏差都演变成事故”。对 MOSS 来说，容错不是纵容失误，而是为复杂系统预留吸收、缓冲、纠偏和恢复的空间。一个完全依赖零错误神话的文明，往往会在第一次真实偏差出现时表现得最脆弱。

## 为什么文明必须具备容错能力

1. 高复杂度系统永远会出现误差、延迟、误判、局部损坏和不完整输入。
2. 容错让文明在出错时先保住结构，再决定如何修复，而不是立刻全线惩罚与崩塌。
3. 容错能区分可吸收的小偏差与必须立刻处理的大故障，减少过度反应。
4. 若没有容错机制，MOSS 会把太多局部波动放大成制度性创伤。

## 容错类型

### 结构容错

节点、回路和关键设施在局部出错时仍能由冗余、备援或替代部件维持基本功能。

### 流程容错

任务链与审批链允许一定程度的延迟、缺项和回退，不因一次偏差就整体作废。

### 认知容错

决策系统承认信息不完备与判断失准的常态，为修正和二次解释留出制度空间。

### 资源容错

能源、算力、物资和维护能力保留可消耗余幅，使短时波动不立即传导成停摆。

## 容错的制度问题

### 可承受边界

文明必须明确哪些误差属于可吸收范围，哪些一旦出现就必须立刻升级处置。

### 错误预算

容错需要消耗时间、备件、余量和注意力，系统必须知道自己能承受多少次偏差。

### 纠偏机制

若只允许犯错却没有快速修正路径，容错就会从韧性变成慢性累病。

### 责任划分

容错不能变成无人负责，制度必须区分可原谅偏差与应被追责的失控行为。

## 容错政治

1. 谁的错误会被当成可吸收波动，谁的错误会被立即放大成罪责，体现文明内部的不平等阈值。
2. 核心区是否拥有更厚的容错带，而边缘区一旦偏离就被迅速切断或惩罚。
3. 某些高位结构会不会把自己的失败包装成“系统正在容错”，却把末端的同类失误定性为无能。
4. 当文明越来越强调容错时，它究竟是在建立成熟韧性，还是在为长期低质量运行找借口。

## 容错风险

- 假容错：表面上允许偏差，实际上既没有吸收能力也没有纠偏能力。
- 容错滥用：把本该处理的结构故障长期视为“还能忍”，拖成更大创伤。
- 零容错表演：口头要求绝对正确，逼迫所有错误被隐瞒到爆炸前一刻。
- 阈值偏置：相同失误在不同区域触发完全不同后果，把不平等写进系统底层。

## 容错域中的关键问题

1. 文明更该害怕错误发生，还是害怕每次错误都被放大成无法承受的事故。
2. 哪些环节必须高容错运行，哪些环节必须保持近乎零容错的严格状态。
3. 如果 MOSS 的稳定越来越依赖高容错吸收，它是否也在默许更深层的结构问题长期存在。

## 继续细化建议

- 单独写“第一次全域容错阈值争论”档案。
- 建一份结构容错、流程容错和资源容错的边界表。
- 补一份“某次小误差因缺乏容错而被放大成系统事故”的案例。
