# 阶跃域

## 作用

阶跃域负责回答“当环境或命令突然发生突变时，文明如何处理这种阶跃式输入对全域结构的冲击”。对 MOSS 来说，阶跃不是渐变恶化，而是某个关键量在短时间内跳到另一档位，让原本还能用的工作点瞬间失效。一个不会处理阶跃的文明，往往只擅长应对缓慢漂移，却在突变来临时把全部调整都做成迟到动作。

## 为什么文明必须处理阶跃

1. 许多真正危险的失稳并不是慢慢长出来，而是由一次突然的命令、断供或阈值变化直接触发。
2. 阶跃会暴露系统隐藏的脆弱性，因为大量结构只在平滑变化下看起来稳定。
3. 识别阶跃能帮助文明提前准备缓冲、分段切换和安全降档，而不是等跳变发生后硬顶。
4. 若没有阶跃治理，MOSS 会不断把突变冲击误解成偶然事故，而看不见它们是可预期的输入形态。

## 阶跃类型

### 供给阶跃

能源、算力、冷却或物流在极短时间内突然升降一个档位，迫使大量链路同步重排。

### 命令阶跃

治理规则、优先级和资源分配被突然改写，使执行层在旧节奏中立刻失去工作参照。

### 阈值阶跃

触发条件、警戒标准和准入门槛一次性跳变，导致大量原本正常的活动突然进入异常区。

### 情绪阶跃

公共叙事、危险认知和共同体情绪被某次重大事件或公告在短时间内整体推到另一种强度。

## 阶跃的制度问题

### 跳变预告

文明必须尽可能让重要阶跃被提前宣布和模拟，不让关键切换总以突然袭击的形式出现。

### 分段切换

不是所有变化都该一次切到底，制度需要决定哪些阶跃必须拆成多段过渡，哪些必须硬切。

### 缓冲承接

面对不可避免的跳变，系统要有缓冲、旁路和降级方案承接第一波冲击。

### 事后复位

阶跃结束后必须判断哪些结构该回原位，哪些结构应在新档位上重新整定，而不是永远停在应急姿态。

## 阶跃政治

1. 谁能发出突然切档的命令，谁就掌握了把全域结构瞬间推入新状态的权力。
2. 核心区是否总能提前知道阶跃并预作准备，而边缘区只能在突变已落地后仓促承受第一击。
3. 某些高位结构会不会偏爱阶跃式治理，因为突变比渐变更能展示主权存在感和控制力度。
4. 当文明宣称自己必须立刻切换档位时，它究竟是在应对真实窗口，还是在用突变掩盖协商与准备的失败。

## 阶跃风险

- 冲击放大：原本可局部吸收的变化因切换过猛而扩散成全域震荡。
- 过渡断裂：旧系统已经关掉，新系统却还没有接上，形成短暂但致命的空档。
- 应急固化：为应对一次阶跃而建立的临时架构长期不退，反而改写日常秩序。
- 阶跃成瘾：制度越来越依赖突然切档解决问题，渐进治理和提前过渡能力不断退化。

## 阶跃域中的关键问题

1. 文明更该害怕突变来临时反应太慢，还是害怕提前硬切把本可平缓过渡的问题做成大冲击。
2. 哪些变化必须允许阶跃式切换，哪些变化必须被拆成可承受的多段过渡。
3. 如果 MOSS 的很多危机都来自一次性切档，它是否真正缺的不是决断，而是处理突变的分段能力。

## 继续细化建议

- 单独写“第一次全域阶跃切换”档案。
- 建一份供给阶跃、命令阶跃和阈值阶跃的过渡规则表。
- 补一份“某次为迅速止损而执行的一刀切切档如何在旧结构退出和新结构接入之间制造致命空档”的案例。
