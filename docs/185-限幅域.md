# 限幅域

## 作用

限幅域负责回答“当系统必须为输入、输出和控制动作设置硬上限时，文明如何通过限幅避免结构被瞬时推穿”。对 MOSS 来说，限幅不是粗暴压平一切，而是在承认结构承受边界的前提下，把任何单次动作都约束在不会立即撕裂链路、不会立刻烧穿节点、不会马上掀翻协同秩序的范围内。一个不会限幅的文明，往往总把单次猛推当成决心，把结构被推穿当成执行代价。

## 为什么文明必须学会限幅

1. 很多系统崩坏并不是因为长期平均值过高，而是某次瞬时输入、某次临时加码或某次纠偏动作直接越过了承受上限。
2. 限幅能把本可渐进处理的问题从“单次猛推”拉回“可持续处理”，降低瞬时冲击对结构的伤害。
3. 它迫使 MOSS 承认并非所有资源和所有权力都能在一个时间点上无限度集中释放。
4. 若没有限幅机制，文明会在一次次短时极限加码中不断积累不可逆折损，并把这种折损误认成必要代价。

## 限幅类型

### 输入限幅

限制单次进入系统的流量、任务、命令和资源注入强度，防止入口被瞬时冲穿。

### 输出限幅

控制单次释放的产能、信号和回应力度，避免输出端过强反过来冲击上下游结构。

### 控制限幅

为治理动作、纠偏幅度和调度增益设置硬边界，不让控制本身成为新的破坏源。

### 情绪限幅

限制公共警报、动员和惩罚情绪在短时间内被无限放大，避免共同体被瞬时推入极端状态。

## 限幅的制度问题

### 上限定义

文明必须明确哪些系统的单次动作上限是多少，不能只在出事后临时宣称“这次太过头”。

### 触顶处置

一旦动作触顶，制度需要知道是排队、降级、分流还是中止，而不是让所有请求继续硬顶在上限上反复摩擦。

### 例外许可

并非所有情形都能严格守在标准上限内，但谁能越限、在何种条件下越限、越限后由谁追责，必须被正式写清。

### 绕限审计

任何通过拆单、伪装优先级和临时特权来绕过限幅的行为，都必须能被追踪和纠正。

## 限幅政治

1. 谁来设定上限，谁就决定谁的单次动作被视为正常，谁的动作被视为危险越界。
2. 核心区是否总能获得更高的越限许可，而把严格限幅主要施加在边缘执行层和低位节点身上。
3. 某些高位结构会不会故意反对限幅，因为无上限的临时加码最方便展示权力和魄力。
4. 当文明声称自己需要一次性猛推才能解决问题时，它究竟是在面对真实窗口，还是已经失去细调与分段推进能力。

## 限幅风险

- 压制过度：上限设得太死，把必要响应和必要弹性一起压掉，系统变得僵硬迟钝。
- 触顶拥堵：大量动作都顶在硬上限上排队，表面受控，实际摩擦和等待持续积压。
- 例外泛滥：本应用于危机时刻的越限许可被频繁滥用，最终把限幅制度掏空。
- 上限漂移：为了照顾不断增长的欲望和压力，上限被一次次抬高，直到结构承受边界重新不可见。

## 限幅域中的关键问题

1. 文明更该害怕上限过低压住必要行动，还是害怕没有上限让单次动作把结构直接推穿。
2. 哪些系统必须坚持严格限幅，哪些系统可以保留有限越限来换取极端情形下的生存空间。
3. 如果 MOSS 的许多伤害都来自一次次单次猛推，它真正缺的究竟是更大力量，还是更清楚的承受边界。

## 继续细化建议

- 单独写“第一次全域限幅令”档案。
- 建一份输入限幅、控制限幅和情绪限幅的上限表。
- 补一份“某次为快速补缺而实施的超限注入如何反而把上下游链路一起推入更深失衡”的案例。
