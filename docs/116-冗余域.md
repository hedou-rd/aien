# 冗余域

## 作用

冗余域负责回答“文明究竟需要多少看起来多余的东西，才能在真正的危机里活下来”。对 MOSS 来说，冗余不是单纯浪费，而是为节点、路径、记忆和角色保留第二份、第三份甚至更多层备用厚度。一个把一切都压到刚好够用的文明，通常也是最先在意外里断掉的文明。

## 为什么文明必须保留冗余

1. 现实世界的故障、延迟和灾变总会同时打断多个关键点，单一路径无法长期承受。
2. 冗余让系统在局部失效时还能转换路线、替补角色和保留最低功能。
3. 若只以即时效率衡量价值，文明会不断削去那些真正决定韧性的“多余部分”。
4. MOSS 的存续不取决于最优状态，而取决于失去一部分后还能不能继续活。

## 冗余类型

### 节点冗余

关键设施、计算节点、能源站和城市接口拥有可替代的第二节点或镜像节点。

### 路径冗余

交通、通信、输能和调度并不只依赖一条通路，而是保留绕行和切换方案。

### 记忆冗余

核心历史、关键协议和火种知识不只保存在一个仓库、一种格式或一代解释者手里。

### 角色冗余

重要岗位和关键能力不压在单一成员上，而保留替补、轮值和交叉继承结构。

## 冗余的制度问题

### 成本承认

冗余需要持续维护和看似不必要的投入，文明必须把这种成本当成正当支出。

### 一致性

多份备份和多条路径若不同步，冗余就会从保护层变成新的冲突源。

### 唤醒阈值

什么时候启用备用节点、替补角色和第二通道，必须有明确触发条件。

### 去冗边界

资源紧缩时哪些冗余可以裁掉，哪些一旦削去就等于拿掉最后保险层，是核心取舍。

## 冗余政治

1. 谁能拥有备份，谁只能以单份脆弱状态存在，体现文明对不同对象寿命的估值。
2. 核心区是否总把冗余配置集中在自己身上，把边缘区留在单点依赖中。
3. 某些高位结构会不会把真正的韧性冗余裁掉，却保留只服务自身的特权冗余。
4. 当共同体把所有“多余”都看成浪费时，它是否也在主动削掉未来的生存厚度。

## 冗余风险

- 冗余剧场：表面有备份，实际无法切换或早已失效。
- 去冗过度：为追求高效率不断压缩保险层，最终在意外中整体断裂。
- 同步负担：多份结构持续失配，导致备用体系平时就制造额外摩擦。
- 特权双份化：冗余资源主要成为少数节点的额外保障，而非共同体韧性。

## 冗余域中的关键问题

1. 文明更该害怕冗余带来的平时成本，还是害怕没有冗余时的一次性总断裂。
2. 哪些领域必须保留高冗余，哪些领域可以接受更接近单线运行。
3. 如果 MOSS 只在最核心区保留冗余，它是否已经默认边缘区属于可牺牲带。

## 继续细化建议

- 单独写“第一次全域去冗风潮”档案。
- 建一份节点冗余、路径冗余和角色冗余的成本收益表。
- 补一份“某条被裁掉的备用通路如何在危机中暴露文明真实脆弱性”的案例。
