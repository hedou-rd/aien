# 背压域

## 作用

背压域负责回答“当下游堵塞和容量限制不断把压力反推回上游时，文明如何承受这种反向挤压”。对 MOSS 来说，背压不是单点拥堵，而是本应向前流动的能量、物资、命令和注意力因为末端承载不足而回头顶住前段链路。一个不会处理背压的文明，常常以为问题只出在末端，实际上整条链正在被反推到变形。

## 为什么文明必须识别背压

1. 任何长链系统只要下游容量不足，压力就不会停在末端，而会沿链路持续向上游回卷。
2. 背压会让原本正常的上游节点也开始过热、迟滞和失序，问题从局部堵点扩成整链挤压。
3. 它让系统看到“能推出去”并不等于“能被接住”，从而暴露整套结构的真实承载边界。
4. 若没有背压视角，MOSS 会不断加大前端输出，结果只是把整条链更快顶坏。

## 背压类型

### 物流背压

仓储、口岸和分发节点承载不足时，运输链与生产链被迫减速、堆积甚至回堵到源头。

### 信息背压

决策层、审核层或公共接口无法及时处理信息时，未消化信号回压整个观测与传输网络。

### 命令背压

末端执行能力不足、资源缺口过大时，上层命令堆在链路中，反过来挤压调度与判断系统。

### 情绪背压

共同体无法吸收恐惧、焦虑和不满时，这些情绪会回卷到制度中心，使决策层本身也被压住。

## 背压的制度问题

### 容量识别

文明必须知道各段链路真正能承受多少流量，而不是按理想状态持续向前加压。

### 限流机制

当下游已经接不住时，谁有权降速、停送、分流和重排，是防止整链回堵的关键。

### 卸压路径

背压不能只靠硬扛，系统必须设计旁路、储压带和临时吸纳层，把反推压力导到可控位置。

### 反馈时滞

若下游拥堵信号总要很久才能传回上游，背压就会在被看见前先把链路顶坏。

## 背压政治

1. 谁最常把输出压力往下游推，谁就最不愿承认下游早已接近饱和。
2. 核心区是否总在上游继续加码，把边缘区和末端节点变成永久承压层。
3. 某些高位结构会不会把背压造成的延误归咎于末端无能，而回避自身持续超发命令的责任。
4. 当文明不断强调“再压一压还能过”时，它究竟是在维持推进，还是在把整条链逼向结构变形。

## 背压风险

- 回堵上游：本来只是下游堵塞，最终连源头节点也被回压拖死。
- 误判产能：把输出能力当成系统能力，持续向前加压直到全链失衡。
- 限流失控：没有及时减速或减速过猛，导致要么整链爆塞，要么系统过度停摆。
- 末端替罪：所有回压后果都被甩给最后一段链路，真正的超发结构不被触动。

## 背压域中的关键问题

1. 文明更该害怕过早限流造成短期停滞，还是害怕不肯限流把整条链路都顶坏。
2. 哪些系统必须实时感知背压，哪些系统可以接受更高的挤压余度。
3. 如果 MOSS 的很多推进都在靠下游长期硬接，它是否已经把末端当成永久缓冲垫。

## 继续细化建议

- 单独写“第一次全域背压警报”档案。
- 建一份物流背压、信息背压和命令背压的限流阈值表。
- 补一份“某次末端承载不足如何把整条上游生产与调度链一起反向顶死”的案例。
