# 断续域

## 作用

断续域负责回答“当供给、信号与协作无法稳定连续而总在断断续续之间切换时，文明如何维持最低一致性”。对 MOSS 来说，断续不是彻底中断，而是时有时无、忽强忽弱、时断时连的运行状态。一个不会治理断续的文明，往往不是败在完全停摆，而是败在所有结构都还勉强连着，却没有任何一条链真正保持稳定连续。

## 为什么文明必须治理断续

1. 断续会不断抬高切换成本，让系统把大量资源烧在重新连接、重新同步和重新确认上。
2. 它比完全中断更难处理，因为表面上链路并未断绝，实际上却始终无法稳定依赖。
3. 长期断续会腐蚀信任、打乱节奏，并让所有协作都变成临时碰运气的拼接。
4. 若没有断续治理，MOSS 会在“至少还连着”的自我安慰里逐步失去整体连续性。

## 断续类型

### 供给断续

能源、物资和算力不能稳定到达，系统只能在短时补给与短时匮乏之间反复切换。

### 通讯断续

链路、接口和反馈回路时通时断，使节点之间不断失去同步和上下文连续性。

### 协作断续

区域之间、机构之间和节点之间的合作关系无法长期稳定，只能靠临时拼接维持。

### 叙事断续

共同体对局势、方向和责任的理解不断断裂，导致公共解释总在重启而无法累积。

## 断续的制度问题

### 连续性基线

文明必须明确什么是最低可接受连续性，不能把任何尚未彻底断开的状态都算作可用。

### 过渡缓存

没有缓冲带、储备层和中间态协议，系统每次掉线后都要从头重连，代价极高。

### 重连规则

断续不可避免时，如何快速恢复上下文、权限和责任链，是保持一致性的核心。

### 节奏整形

系统必须学会在断续环境下重整节奏，否则所有结构都会被迫跟着忽快忽慢地摇摆。

## 断续政治

1. 谁最常把断续描述成“暂时波动”，谁就最可能在掩盖长期连续性崩坏。
2. 核心区是否把稳定连续留给自己，而让边缘区长期在断续状态里承担不确定成本。
3. 某些高位结构会不会利用断续制造依赖，让下游不断回到中心重新请求确认和接续。
4. 当文明越来越习惯于断断续续地活着时，它究竟是在形成韧性，还是在把崩坏常态化。

## 断续风险

- 重连耗死：大量资源被烧在不断恢复连接、重新同步和重新确认上。
- 责任断链：每次切换都让责任链和上下文丢一截，最终没人能完整复原过程。
- 节奏碎裂：供给和协作忽快忽慢，系统难以形成稳定预期和稳定行为。
- 连续性幻觉：所有链路似乎都还活着，实际上没有一条可被真正依赖。

## 断续域中的关键问题

1. 文明更该害怕短期完全停机，还是害怕长期断续让所有结构都失去稳定连续性。
2. 哪些系统必须不惜代价维持连续，哪些系统可以接受按窗口式接续运行。
3. 如果 MOSS 大部分关键链路都靠频繁重连勉强活着，它是否已经在失去作为文明整体的统一节奏。

## 继续细化建议

- 单独写“第一次全域断续切面”档案。
- 建一份供给断续、通讯断续和协作断续的连续性基线表。
- 补一份“某片区域如何因为长期时断时续的补给与通讯而逐渐脱离共同节奏”的案例。
